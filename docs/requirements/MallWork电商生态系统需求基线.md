# MallWork 电商生态系统需求基线

_MallWork 当前需求的唯一业务基线，覆盖 24 项能力需求和 59 条验收场景。_

---

## 📋 状态与范围

| 状态 | 判定标准 |
| --- | --- |
| 已实现 | 当前代码中已有完整能力及验证证据 |
| 已具备底座 | 已有部分基础设施或链路，尚未满足完整需求 |
| 规划中 | 已确定目标、边界与验收条件，尚未交付 |

所有需求均遵守以下系统级约束：

- MallWork 是统一控制面，通过 Store Adapter 访问独立站或第三方平台
- 所有请求、任务、数据和副作用均携带 tenant、store、actor 与权限范围
- 数字老板负责编排和监督，数字员工负责专业执行，两者都不能直接写站点数据库
- 所有写操作必须具备幂等、版本校验、风险策略和审计记录
- 高风险动作必须经过有效人工审批或边界明确的预授权策略
- 外部服务不可用时必须显式降级、停止或进入对账，不能伪造成功

## 🌐 站点接入与部署

站点能力由 [Store Adapter v1](../contracts/store-adapter-v1.md) 定义。当前需求包括 Catalog、Inventory、Pricing、Orders、Customers、Content/SEO、Marketing、Analytics 和 Deployment 九个能力组。

标准独立站必须使用版本化模板和 Connector SDK，并满足以下发布门禁：

1. 生成不可变构建物及 manifest
2. 通过单元、端到端、可访问性和安全检查
3. 创建与生产隔离的预览环境
4. 生产发布获得有效审批
5. 发布后执行真实健康检查
6. 健康失败时自动回滚到上一健康版本
